Meta API Oficial (WhatsApp) - O que pedir ao cliente + previsao de custos

Documento de apoio para onboarding comercial e tecnico de clientes que vao usar a API oficial da Meta no WhatsApp Business Platform (Cloud API).

Data de referencia desta previsao: 26/02/2026.

1) Checklist: o que o cliente precisa fornecer

Item Obrigatorio Detalhe pratico
Acesso admin ao Meta Business Portfolio Sim Sem permissao de admin nao e possivel concluir configuracao de WABA, numero e billing.
WABA (WhatsApp Business Account) Sim Pode ser criado no onboarding. Se ja existir, pedir o ID e acesso.
Numero de telefone comercial Sim Numero para API oficial. Definir se sera novo numero, migracao ou coexistencia.
Token de acesso (preferencia: system user) Sim Usar token com escopos whatsapp_business_management e whatsapp_business_messaging.
Webhook publico HTTPS Sim URL de callback + verify token para receber eventos e status de mensagens.
PIN de 6 digitos para registrar numero Sim Necessario no registro do phone number na Cloud API (2-step verification).
Metodo de pagamento no Meta Business Sim Meta cobra diretamente o uso da API oficial (templates e demais custos aplicaveis).
Templates (marketing, utilitario, autenticacao) Sim Definir textos por caso de uso para aprovar e enviar com compliance.
Dados de negocio (CNPJ, razao social, site, politica) Recomendado Ajuda em verificacao, qualidade e continuidade operacional da conta.

2) Checklist tecnico minimo para entrada em producao

  1. Confirmar que o numero foi registrado e vinculado ao WABA correto.
  2. Configurar webhook e validar recebimento de eventos.
  3. Submeter e aprovar templates essenciais (boas-vindas, lembretes, confirmacoes, notificacoes).
  4. Enviar mensagem de teste por API e validar status de entrega.
  5. Conferir billing e monitoramento de qualidade do numero.
Boa pratica: iniciar com templates utilitarios (baixo custo) e escalar marketing gradualmente para manter previsibilidade financeira.

3) Premissas de custo usadas nesta previsao (estimativa)

  • Modelo: cobranca por mensagem template (Marketing, Utility, Authentication).
  • Mercado considerado: Brazil.
  • Moeda base da tabela: USD.
  • List rate (Brazil): Marketing 0.0625, Utility 0.0068, Authentication 0.0068.
  • Sem adicionar markup de BSP/plataforma, sem impostos locais e sem variacao cambial.
Estes valores sao previsao de referencia comercial. A cobranca real depende de: categoria de template, pais do destinatario (DDI), volume mensal (tiers), janela de servico e eventuais taxas do seu provedor/plataforma.

4) Formula rapida de previsao mensal

Custo USD = (QtdMarketing x 0.0625) + (QtdUtilityCobrada x 0.0068) + (QtdAuth x 0.0068)

Em volumes maiores, Utility e Authentication podem reduzir por tiers (rate card por faixa de volume).

5) Simulacao de gasto por volume (cenarios)

Leitura: cada cenario usa um mix diferente de mensagens. Serve para previsao comercial, nao como fatura final.

6) Exemplo pronto para proposta comercial

Exemplo: cliente com 20.000 mensagens/mes, mix de 20% marketing, 55% utility cobrada, 25% sem custo direto.

Calculo: (4.000 x 0.0625) + (11.000 x 0.0068) = 250 + 74.8 = US$ 324.80/mes (antes de taxas da plataforma e impostos).

7) Pontos para alinhar com o cliente antes de fechar

  • Quem sera responsavel por aprovar e manter templates.
  • Qual percentual esperado de mensagens de marketing no mes.
  • Quais fluxos vao usar utility dentro da janela de servico (24h).
  • Se havera envio internacional (impacta rate card por pais).
  • Se existe custo adicional do BSP/plataforma sobre a tarifa Meta.
